# 架构说明

个人工作台是一个**纯前端、零后端依赖**的本地应用：所有数据保存在浏览器
localStorage（端到端加密云同步为可选能力），构建产物是静态文件，`npm run dev`
即可跑起全部功能。本文说明代码分层与三类扩展（模块 / 生活看板 / 首页卡片）的标准步骤。

## 分层总览

```
src/
  main.jsx        入口（装配主题、样式、App）
  app/            外壳层 —— 应用骨架，不理解任何具体业务
  components/     共享 UI 层 —— 跨模块复用的组件与拖拽基建
  boards/         生活看板 —— 同一引擎驱动的多类型看板（feature）
  modules/        扩展模块 —— 自包含的大功能（面试 / 资金）
  widgets/        首页卡片 —— 控制台的可插拔速览卡
  styles/         样式（外壳全局 + 模块作用域 + 主题）
```

依赖方向单一：`app → modules/boards/widgets → components → app/store.js`。
外壳只认注册表（模块清单、看板类型表、卡片注册表），不 import 任何具体页面，
因此扩展只需"注册"，不需改动外壳。

## 外壳层（src/app/）

| 文件 | 职责 |
| --- | --- |
| `App.jsx` | 侧栏分组菜单（可折叠）+ 面包屑 + 权限守卫 + 统一加载/错误态 |
| `router.js` | hash 路由：外壳固定页 + 模块路由聚合 + 生活看板动态路由 + 旧链接重定向 |
| `menu.js` | 菜单树唯一真实来源（顺序/显隐/权限码均由此派生） |
| `permissions.js` | `usePermissions()`：以节点可见性实现轻量权限，预留账号体系映射 |
| `navigate.js` | 统一跳转 + 旧应用全局导航钩子垫片（`__iwNavigate` / `__fpNavigate`） |
| `theme.js` | 深浅色主题（`wb:theme`，`auto` 跟随系统，引导脚本防 FOUC） |
| `store.js` | 外壳存储层：`useLocalState`（跨组件即时同步）、`useDragLayout`（通用拖拽布局）、`WB` 键表 |
| `export-data.js` | 全量导出/导入共享层（设置页与首页一键导出共用同一份逻辑） |
| `HomePage.jsx` | 控制台首页（可拖拽 widget 网格） |
| `SettingsPage.jsx` | 全局设置（外观 / AI 接入 / 数据管理 / 模块显示与排序 / 关于） |

## 模块清单机制（扩展性核心）

每个扩展模块在自己的目录里放一个 `manifest.js`，**一站式声明**菜单节点、路由与旧链接兼容：

```js
// src/modules/<name>/manifest.js
import { lazy } from 'react'
const Page = lazy(() => import('./pages/Page.jsx'))

export default {
  id: 'demo',                       // 模块 id（路由前缀 / 权限码前缀）
  name: '演示模块', icon: '🧩', tone: 'blue',
  permission: 'demo.view',
  children: [ /* 侧栏子节点：{ id, name, icon, desc, path, permission } */ ],
  routes: [ /* { path, el|redirect, props?, title } */ ],
  legacy: { prefix: '/dm', tabs: [...], fallback: '...' }  // 可选：旧链接兼容
}
```

然后在 `src/modules/index.js` 追加一行注册：

```js
import demo from './demo/manifest.js'
export const MODULE_MANIFESTS = [interview, fund, demo]
```

外壳会自动完成：菜单组与子节点并入侧栏（可拖拽排序/显隐）→ 路由注册（懒加载分包、
面包屑 `[模块名, 页面名]`）→ 权限码 `<module>.<page>.view` 生效 → 首页「模块入口」卡同步。
**除 manifest 与 index.js 之外，外壳零改动。**

## 新增生活看板类型（boards/）

生活看板是"一个引擎 + 多种类型"：`BoardPage` 按 `boardId` 取看板定义并渲染对应类型组件。

1. `boards/registry.js` 的 `BOARD_TYPES` 登记类型（label / icon / desc / 备选图标）；
2. 新建 `boards/XxxBoard.jsx` 类型组件，并在 `BoardPage.jsx` 的类型映射中接入；
3. 需要默认数据时在 `boards/seed.js` 补充。

内置看板在 `registry.js` 的 `BUILTIN_BOARDS` 固定登记（菜单子节点与之 id 对应）；
用户自建看板存 `wb:custom-modules`，自动挂到「生活看板」组并获得动态路由
`/workbench/life/<id>`，数据键为 `wb:board:<id>`。

## 新增首页卡片（widgets/）

1. 新建 `widgets/Xxx.jsx`，接受 `{ hidden }` 之类的通用 props；
2. `widgets/registry.js` 登记 `{ id, name, icon, render }`；
3. 完成。排序/显隐由用户在页面上拖拽控制，存 `wb:layout:<profile>`；
   新卡片 id 会自动补进老用户的已存顺序末尾，无需数据迁移。

## 存储键约定

| 前缀 | 归属 | 示例 |
| --- | --- | --- |
| `wb:*` | 外壳 | `wb:layout:<profile>`、`wb:menu-order`、`wb:module-visibility`、`wb:board:<id>`、`wb:theme` |
| `iw:*` | 面试模块 | `iw:resumes`、`iw:pipeline`、`iw:ai-config` |
| `fp:*` | 资金模块 | `fp:modules`、`fp:snapshots`、`fp:expenses`、`fp:budget` |

读写统一经 `app/store.js` 的 `useLocalState`（`wb:ls-change` 事件保证跨组件即时同步）；
各模块内部 store 保持同构 API，互不干扰。

## 拖拽体系

全站拖拽（首页网格、看板卡片、设置页模块管理、各模块分区卡）复用
`components/dnd/magpie.jsx` 一套 @dnd-kit 封装：把手拖动 / 占位 / 平滑让位 /
浮层克隆 / 容器边界 / 最近网格碰撞，键盘可达（抓手聚焦后方向键排序）。
页面只需提供条目注册表 + `useDragLayout(storageKey, allIds)`。

## 旧链接兼容

合并前的两个独立应用无路由（页签 key），工作台保留全部旧入口：
`#/interview`、`#/fund`、`#/iw/<页签>`、`#/fp/<页签>`、`#/console` 等
由 `app/router.js` 的 `LEGACY` 表与各模块 manifest 的 `legacy` 字段重定向到统一路由；
模块内部旧跳转钩子（`__iwNavigate` / `__fpNavigate`）由 `app/navigate.js` 垫片映射。
